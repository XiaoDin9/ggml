# ggml 项目简介

本文用于了解 ggml 的定位、目录结构、模块职责和源码阅读路线。内容依据本地工程整理，详细编译、运行和调试步骤见 [项目简介和编译](项目简介和编译)。

## 1. 项目概况

| 项目 | 说明 |
|---|---|
| 名称 | ggml |
| 定位 | 面向机器学习的张量计算库 |
| 主要语言 | C、C++，部分后端包含设备计算内核 |
| 构建系统 | CMake |
| 许可证 | MIT |
| 本地版本 | `0.25.3`，依据根目录 `CMakeLists.txt` 的版本定义 |
| 本地目录 | `C:\Users\yding\Desktop\dy_ws\01_code\ggml-master` |
| 核对日期 | 2026-10-02 |

ggml 提供张量、算子、计算图、内存管理和计算后端等组件。开发者可以使用这些组件描述神经网络，并在 CPU、GPU 或其他加速设备上执行计算。

它的主要设计目标是简单、可移植和高效。核心代码以 C/C++ 实现，不同硬件的优化实现放在独立后端中，应用通过公共接口使用这些能力。

模型的网络结构、权重加载和输入输出处理通常由应用代码负责。本工程的 `examples/` 展示了如何使用 ggml 实现文本生成、图像识别、目标检测等任务。

## 2. 主要功能

- **张量与算子**：支持矩阵乘法、卷积、加法、激活、归一化和注意力相关运算。
- **计算图**：组织算子之间的依赖关系，将模型描述交给后端执行。
- **量化**：提供多种低位数数据表示以及量化、反量化和相关计算实现。
- **内存规划**：为计算图分配和复用张量数据的存储空间。
- **多后端执行**：提供统一接口接入 CPU、GPU、专用加速设备及远程计算。
- **GGUF 文件读写**：保存和读取模型元数据、张量描述及张量数据。
- **训练与评估**：包含自动微分、优化器、数据集和结果统计等功能。

训练功能的适用范围需结合算子和后端支持判断。当前 MNIST 示例的 README 明确说明，ggml 训练功能仍在开发中，尚未达到生产就绪状态。

## 3. 核心概念与工作流程

| 概念 | 作用 | 主要对象或接口 |
|---|---|---|
| 张量 | 描述数据类型、维度、步长、数据位置和算子来源 | `ggml_tensor` |
| 上下文 | 管理张量、计算图等对象的内存；数据内存也可交给后端分配 | `ggml_context`、`ggml_init()` |
| 算子 | 描述一次运算及其输入，形成计算图节点 | `ggml_mul_mat()`、`ggml_add()` 等 |
| 计算图 | 表示计算节点及其依赖关系 | `ggml_cgraph`、`ggml_build_forward_expand()` |
| 后端 | 在具体设备上执行计算，管理缓冲区和数据传输 | `ggml_backend_t` |
| 调度器 | 安排不同后端上的计算与数据传输 | `ggml_backend_sched_t` |
| GGUF | 模型数据的文件格式 | `gguf.h` |

创建算子与执行算子是两个阶段。例如，`ggml_mul_mat(ctx, a, b)` 创建矩阵乘法节点，实际计算在后端或调度器执行计算图时发生。

典型使用流程如下：

```text
初始化设备后端和上下文
    ↓
创建张量并描述模型运算
    ↓
构建计算图
    ↓
准备内存，写入模型权重和输入
    ↓
由后端或调度器执行计算图
    ↓
读取结果，释放资源
```

### 4.1 源码与接口

`include/` 表示“应用能调用什么”，`src/` 表示“这些接口怎样实现”。阅读一个功能时，可以从头文件中的接口声明进入，再查核心实现和具体后端。

### 4.2 文档与维护目录

- `docs/gguf.md` 说明 GGUF 文件结构。
- `cmake/` 包含通用编译配置、NCCL 查找、Git 信息获取，以及供外部工程使用的 CMake 包配置模板。
- `ci/run.sh` 组织不同配置和后端的构建与测试。
- `.github/workflows/` 包含自动构建、测试和发布流程；`.github/actions/` 包含复用组件，例如编译缓存管理。
- `scripts/` 包含发布脚本，以及与 `llama.cpp`、`whisper.cpp` 同步代码的维护工具。
- `.vscode/launch.json` 配置本地 `mnist-eval` 的调试方式。
- `.pi/gg/SYSTEM.md` 保存编码助手规则，不参与计算库编译。
- `.editorconfig`、`.gitignore`、`.gitmodules` 分别用于编辑格式、忽略规则和子模块配置。

### 4.3 构建目录

`build/` 是生成目录，主要包括：

| 路径 | 作用 |
|---|---|
| `bin/Debug/`、`bin/Release/` | Visual Studio 构建的程序、DLL 和调试符号 |
| `src/`、`examples/`、`tests/` | 对应目标的构建文件与中间产物 |
| `CMakeFiles/`、`.cmake/` | CMake 内部文件与工具接口生成信息 |
| `Testing/` | 测试运行记录 |
| `x64/`、`*.dir/` | Visual Studio 构建中间文件 |
| `CMakeCache.txt` | 构建选项、工具链和依赖路径缓存 |
| `ggml.slnx`、`*.vcxproj` | 当前生成器输出的 Visual Studio 解决方案和工程 |

这些路径来自本地 Visual Studio 构建，其他工具链的生成文件和输出布局可能不同。修改功能时应编辑源码目录中的文件，构建文件通常由 CMake 重新生成。

## 5. 核心模块及源码对应关系

| 模块 | 公共接口 | 主要实现 | 职责 |
|---|---|---|---|
| 核心张量与计算图 | `include/ggml.h` | `src/ggml.c` | 张量创建、算子定义、计算图构建和自动微分 |
| 计算后端与调度 | `include/ggml-backend.h` | `src/ggml-backend.cpp` | 后端抽象、缓冲区、数据传输和多后端调度 |
| 内存分配 | `include/ggml-alloc.h` | `src/ggml-alloc.c` | 张量和计算图内存分配及复用 |
| 训练与评估 | `include/ggml-opt.h` | `src/ggml-opt.cpp` | 数据集、损失、优化器及结果统计 |
| 模型文件 | `include/gguf.h` | `src/gguf.cpp` | GGUF 文件读写 |
| C++ 辅助封装 | `include/ggml-cpp.h` | 主要位于头文件 | 通过智能指针等方式管理对象生命周期 |
| 通用量化 | 内部头文件 `src/ggml-quants.h` | `src/ggml-quants.c` | 量化和反量化 |

其他重要实现包括：

- `ggml-backend-reg.cpp`：后端注册、设备发现和加载入口。
- `ggml-backend-dl.cpp`：动态库加载的平台封装。
- `ggml-threading.*`：线程同步辅助功能。
- `ggml.cpp`：C++ 异常终止时的回溯等辅助处理。
- `ggml-impl.h`、`ggml-common.h`、`ggml-backend-impl.h`：内部定义和后端实现接口。

## 6. 硬件后端目录

`src/ggml-*` 中的后端目录负责把统一的计算图转换为具体设备上的执行过程。

| 后端目录 | 作用 |
|---|---|
| `ggml-cpu/` | CPU 算子、多线程、SIMD 优化和量化计算 |
| `ggml-cuda/` | NVIDIA CUDA 计算内核 |
| `ggml-hip/` | AMD HIP/ROCm GPU 后端 |
| `ggml-metal/` | Apple Metal GPU 后端 |
| `ggml-vulkan/` | Vulkan GPU 后端 |
| `ggml-sycl/` | SYCL 后端，本地构建配置面向 Intel 设备 |
| `ggml-opencl/` | OpenCL 后端 |
| `ggml-webgpu/` | WebGPU 后端 |
| `ggml-blas/` | 通过 BLAS 库加速矩阵计算 |
| `ggml-cann/` | Ascend/CANN 加速后端 |
| `ggml-musa/` | MUSA 加速后端 |
| `ggml-hexagon/` | Hexagon 加速后端 |
| `ggml-openvino/` | OpenVINO Runtime 后端 |
| `ggml-zdnn/` | IBM zDNN/NNPA 加速后端 |
| `ggml-zendnn/` | AMD ZenDNN 加速后端 |
| `ggml-et/` | ET 平台加速后端 |
| `ggml-rpc/` | 通过 RPC 调用远端设备执行计算 |
| `ggml-virtgpu/` | VirtGPU/Virglrenderer 计算接口转发 |

后端目录存在不代表已经启用。构建时通过 `GGML_CPU`、`GGML_CUDA` 等 CMake 选项选择后端，实际算子支持也因后端而异。

主要内部子目录如下：

| 子目录 | 作用 |
|---|---|
| `ggml-cpu/arch/` | 按 x86、ARM、RISC-V、LoongArch、PowerPC、s390 和 WASM 划分的优化实现 |
| `ggml-cpu/amx/` | Intel AMX 优化 |
| `ggml-cpu/kleidiai/`、`llamafile/`、`spacemit/` | 优化库接入或特定平台加速 |
| `ggml-cpu/cmake/` | CPU 特性与依赖检测 |
| `ggml-cuda/template-instances/`、`vendors/` | 模板实例化和厂商适配 |
| `ggml-vulkan/vulkan-shaders/`、`cmake/` | 计算着色器和构建辅助模块 |
| `ggml-hexagon/htp/` | Hexagon HTP 侧计算代码 |
| `ggml-et/et-kernels/`、`cmake/` | ET 计算内核及其构建、嵌入工具 |
| `ggml-virtgpu/backend/`、`include/` | 转发请求的执行端与相关头文件 |

例如，研究 CPU 矩阵乘法时，可以从 `ggml-cpu/ops.cpp` 进入，再追踪向量运算、量化计算和架构优化代码。

### 7.2 MNIST 示例的源码分工

```text
examples/mnist/
├── mnist-eval.cpp       评估程序入口
├── mnist-train.cpp      ggml 训练程序入口
├── mnist-common.cpp     模型加载、网络构建、数据处理与训练评估实现
├── mnist-common.h       共享结构和函数声明
├── mnist-train-fc.py    PyTorch 全连接模型训练与 GGUF 导出
├── mnist-train-cnn.py   TensorFlow/Keras 卷积模型训练与 GGUF 导出
├── mnist-fc-f32.gguf    本地已有的模型文件
├── data/               数据集
├── web/                浏览器演示资源
├── server.py           浏览器演示服务脚本
├── CMakeLists.txt      定义示例的构建目标
└── README.md           使用说明
```

全连接模型将 `28 × 28` 图片展开为 784 个输入值，经 500 个隐藏单元和 ReLU 后输出 10 个类别的 logits，对应数字 0～9。

`mnist-eval.cpp` 负责读取测试数据、加载模型、构建网络、执行评估，并输出预测数字、损失和准确率。网络结构和模型处理的主要实现位于 `mnist-common.cpp`。

它体现了三个层次的分工：应用负责数据和模型流程，ggml 核心负责描述计算与管理资源，后端负责执行具体运算。

## 8. 构建关系

根目录 `CMakeLists.txt` 先配置工程版本和编译选项，再加入 `src/`。根据 `GGML_BUILD_TESTS` 和 `GGML_BUILD_EXAMPLES` 的值，继续加入测试和示例。

主要库目标的分工是：

- `ggml-base`：核心张量、计算图、内存、量化、训练评估和 GGUF 等实现。
- `ggml`：后端注册与加载等入口，并关联 `ggml-base`。
- `ggml-cpu` 等后端库：提供实际设备执行能力。
- `mnist-eval` 等示例：链接 ggml 与示例共享代码，形成可执行程序。

`requirements.txt` 用于 Python 示例、训练和模型转换。仅编译 C/C++ 核心库通常不需要安装其中的 Python 包；启用特定硬件后端时，需要准备对应工具链和依赖。

Windows CPU/CUDA 构建命令、MNIST 参数、VS Code 调试配置和常见问题见 [项目简介和编译](项目简介和编译)。

## 9. 推荐源码阅读路线

1. 阅读 `README.md`，了解项目目标和基本构建方式。
2. 阅读 `examples/simple/simple-backend.cpp`，掌握张量、计算图、内存和后端的关系。
3. 阅读 `examples/mnist/mnist-eval.cpp`，了解完整评估流程。
4. 阅读 `examples/mnist/mnist-common.cpp`，追踪模型加载与网络构建。
5. 查询 `include/ggml.h`、`ggml-backend.h`、`ggml-alloc.h` 和 `ggml-opt.h`。
6. 追踪 `src/ggml.c`、`ggml-backend.cpp` 和具体后端中的执行实现。
7. 结合 `tests/` 检查输入形状、精度和边界条件。

初次阅读时，可选取矩阵乘法这一条路径贯穿示例、API、核心实现和 CPU 后端，再逐步扩展到卷积、量化和其他后端。
